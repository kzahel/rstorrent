## Reproduced Resume Defect And Bounded Repair

The first integrated run completes, restarts, seeds, pauses, and invalidates
exactly one corrupt piece. Resume then reports Downloading with no queue
position and no peer dial for the entire 30-second deadline. The retained
magnet hint is eligible; this is not discovery backoff. `set_desired_state`
only changes intent, although Tactical 114's accepted contract says Resume
appends an incomplete torrent whose queue position is absent.

Repair that transaction: a retained, nonarchived, nonpending-selection
incomplete torrent receives a missing tail position when Resume is applied.
Preserve existing positions and complete seed status; no reordering, duplicate
position, schema change, or new task. Repeated desired-running Resume repairs
the same absent-position state; request replay remains idempotent. Missing
metadata is incomplete; verified metadata uses current wanted-piece evidence.
Keep all authority in the store, beneath the existing runtime auto-manager.
Add deterministic paused-recheck/resume, queue ordering, exact replay/reopen,
and intact-seed negative evidence, then rerun the unchanged integrated case.

Additional source review: Tactical `114`'s intent/queue distinction;
`download_queue.rs::{append,place_missing}`; libtorrent
`src/torrent.cpp::{resume,do_resume,force_recheck}`. Libtorrent's pause/resume
also resets per-session transfer counters; the harness must take its repair
counter baseline after the source has resumed, not subtract across that reset.
