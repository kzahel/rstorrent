Chromebook setup and troubleshooting

Android setup or connection

A service that does not respond cannot tell us whether Play is available, the app is installed, or your administrator restricts it. Choose the stage you can confirm below. Opening a store link does not confirm installation.

Play is not enabled or setup is unfinished

Open ChromeOS Settings, find Google Play, and finish its setup if offered and permitted. If the option is missing or managed, ask your administrator; do not bypass policy. Use Linux instead where permitted.

Play is available; I need to install the app

Open the JSTorrent Play listing and check the actual installation result. Open JSTorrent from the Launcher after installation. A successor update may not yet be available; the listing alone does not identify the installed engine.

Installation failed, or the app is unavailable

Read the error shown by Play. This extension cannot determine its cause. Resolve the store's stated account, storage, compatibility or policy issue, then retry manually. Preserve your existing apps and data while resolving installation problems. If installation remains unavailable, Use Linux instead.

The installed app did not open

Open JSTorrent directly from the Chromebook Launcher. Confirm any ChromeOS Open with prompt and enable browser control in the app. Then use Connect Android app in the extension popup. The app can also be used directly without extension control.

Browser access or pairing was denied

Use Connect Android app to request the extension's Android-service permission. If Chrome shows a Local Network Access prompt, allow access only if you intend to connect. Open JSTorrent and approve its named extension pairing request. A rejected or expired request needs manual Retry; Cancel stops the page's attempt without changing your library. A canceled pairing attempt can leave its Android approval request pending for up to two minutes; wait for expiry before retrying. Cancel does not dismiss a separate OS launch prompt or revoke an existing pairing.

Saved pairing, update or connection failure

Open the same Android app and retry. If an app update is required, check Play for an available update; if none is offered or your OS is unsupported, use standalone Android or Use Linux instead. An extension update requirement needs the extension update. Re-pair only through explicit Android approval. Browser retries do not start the app automatically.

The download folder is unavailable

In Android Storage settings, repair the original folder binding through the Android folder picker and approve access. ChromeOS Share with Linux does not grant Android access. Preserve unrelated files and existing roots.

The connection page offers a voluntary support-context preview with the failed stage, Android backend, known permission and browser/build versions. Review it before copying to support. Play, app presence and policy remain unknown; no logs are uploaded automatically.

Use Linux instead

This is an explicit switch to a separate Linux library, settings and download folders. Android torrents stay in Android; an empty Linux library does not mean they were lost. Finish or stop Android work before choosing the same payload folder for Linux. No automatic migration occurs.

If Linux is missing or blocked by policy, it may not be available on this device. If neither Android nor Linux is permitted and usable, this Chromebook environment is unsupported. Ask your administrator or use another supported device; repeating installation links cannot resolve that restriction.

ChromeOS Linux runs the Rust torrent engine and serves the complete RSTorrent interface to Chrome. This extension provides the handoff; it cannot wake a fully stopped Linux environment by itself.

Install the preview

  1. Enable Linux development environment in ChromeOS Settings only where offered and permitted.
  2. Use the official authenticated installer from Terminal with curl -fsSL https://rstorrent.com/install-crostini.sh | bash. It verifies the signed release manifest and package hash before installation. A current development candidate is not automatically a published release. For an already authenticated local package, extract it in Linux files.
  3. Open Terminal in that folder and run ./install.sh.
  4. Open RSTorrent for ChromeOS Linux from the Chromebook Launcher. It wakes Linux, starts RSTorrent, and returns to Chrome.

Everyday launch

Use the Chromebook Launcher when Linux may be stopped. Once the local backend is running, this extension’s ChromeOS Linux button opens or focuses its UI. Closing the tab does not stop active torrents.

The extension first opens an offline Linux connection page. Its check requests browser access only to the Linux hostname, validates the responding app, then opens the Linux library. Creating a tab alone does not confirm a connection. Retry checks again without starting Linux; Cancel stops the check.

Linux page unavailable or hostname not found

Open Terminal from the Chromebook Launcher, select penguin if offered, and wait for the Linux command prompt. Then open RSTorrent for ChromeOS Linux from the Launcher and retry the extension's Linux connection.

If Chrome shows ERR_NAME_NOT_RESOLVED, the Linux hostname is unavailable to Chrome. A connection check cannot distinguish this from other network, browser-permission or service failures. If Terminal also fails, resolve its stated error first; reinstalling JSTorrent cannot repair ChromeOS Linux startup.

If Terminal opens but Chrome still cannot find the hostname, close Linux apps, use Terminal's Shut down Linux action, then reopen Terminal and try again. This stops active Linux transfers; your library and downloaded files remain on disk. Do not remove the Linux development environment or delete your library to troubleshoot connectivity.

Developer administration can start a container without completing ChromeOS's normal app/hostname registration. A running container or successful local status check alone does not confirm Chrome can reach it. Use normal Terminal or Launcher startup to complete that path.

Files and recovery

Downloads initially use Linux ~/Downloads. To use a Chromebook folder, choose Share with Linux in the Files app before adding it in RSTorrent.

Check the installed backend
rstorrent-crostini status
Restart the backend
systemctl --user restart com.jstorrent.rstorrent.crostini.service
Remove app files, keep profile and downloads
rstorrent-crostini uninstall
Also remove the Crostini profile
rstorrent-crostini uninstall --purge
